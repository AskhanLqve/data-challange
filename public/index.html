Работа с результатом

Спорная оценка — не тупик.

Оператор оспаривает критерий с комментарием. Проверяющий видит оценку, обоснование ИИ и фрагмент диалога, подтверждает или меняет её с причиной.

  • Переход к реплике и к моменту записи звонка
  • Проверенный участок для пропущенного действия
  • Исходная оценка, решение и финальный итог в карточке

Возможности.

Чек-лист настраивается без кода

Критерии, секции, веса, тип ответа, шкалы и правила N/A. Каждое сохранение — новая версия, старые оценки хранят свою. Заменённый критерий сразу попадает в промпт.

Звонки и запись

Кнопка у каждой реплики перематывает запись к нужному месту.

Точность в цифрах

Эталонная разметка 26 диалогов и 16 пограничных случаев, отчёт по каждому критерию.

Грубые ошибки отдельно

Оскорбление, услуга в обход компании, раскрытие данных — отдельная отметка.

Экспорт и встраивание

CSV и JSON. Интерфейс — веб-компонент для Dynamics 365.

Расчёт итога.
По правилам чек-листа.

  1. «Да» даёт полный вес критерия, «Нет» — ноль.
  2. Шкала пересчитывается пропорционально весу: верхняя ступень даёт полный вес.
  3. Критерий с N/A исключается, его вес делится между применимыми, максимум остаётся 100.
  4. Итог округляется до двух знаков. Если применимых критериев нет, итог не считается.
  5. Грубая ошибка отмечается отдельно и не смешивается с баллами.

Коротко о главном

Чем «Нет» отличается от N/A?

«Нет» — действие было нужно, но оператор его пропустил или выполнил неверно. N/A — критерий неприменим по своему условию, например общий вопрос о тарифе не требует идентификации. Вес критерия с N/A делится между остальными.

Откуда модель знает, что оценивать?

Промпт каждый раз собирается из текущей версии чек-листа: формулировки, шкалы, условия N/A и уточнения. Поменяли критерий в настройках — следующая оценка идёт уже по нему. В карточке оценки видны промпт и ответ модели.

Можно ли доверять баллам?

Модель только выбирает ответ и указывает реплики, арифметику делает код. Точность измеряется командой pnpm eval на эталонной разметке, отчёт показывает совпадение по каждому критерию и все расхождения.

Где хранятся данные?

На сервере сервиса, в JSON-файлах. С локальной моделью транскрипты не покидают компьютер. Ключ облачной модели хранится только на сервере и не попадает в браузер.

Как встроить в Dynamics 365?

Интерфейс — один веб-компонент <cqa-app> из двух файлов без сборки. Его можно подключить как HTML web resource и указать адрес сервиса в атрибуте api-base.
