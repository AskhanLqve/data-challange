# CQA — Conversation Quality Analytics

Прототип для хакатона Freedom Broker. Система оценивает работу оператора в чатах и звонках (RU / KZ / EN) по настраиваемому чек-листу, показывает обоснования со ссылками на реплики и поддерживает апелляции с пересмотром оценки.

## Быстрый старт

Нужны Node.js 20.6+ и pnpm (`npm i -g pnpm` или `corepack enable`).

**1. Модель оценки** — выберите одну:

```bash
# Вариант А — локально и бесплатно (так работает демо): Ollama + Qwen 2.5 7B
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5:7b-instruct

# Вариант Б — облако: ключ Anthropic (Claude Opus 5.5), впишите его в .env
```

**2. Запуск**

```bash
pnpm install
cp .env.example .env          # для Ollama: CQA_PROVIDER=ollama, CQA_MODEL=qwen2.5:7b-instruct
pnpm start                    # лендинг: http://localhost:3000, приложение: http://localhost:3000/app.html
```

**3. Первые шаги в приложении:** «Диалоги» → `group_id` = `DEV` → «Загрузить из API» → «Оценить все показанные».
Откройте любой диалог — экран «Анализ разговора».

**Как проверить, что всё работает**

| Команда | Что проверяет | Нужна модель |
|---|---|---|
| `pnpm test` | расчёт баллов, API, формат results.json, правила кодом, метрики разговора (29 тестов) | нет |
| `pnpm check` | готовность к демо: сервер, модель, API организаторов, чек-лист, оценки, формат results.json, замер точности | нет |
| `pnpm eval` | точность ИИ на эталонной разметке (26 диалогов DEV + 16 пограничных случаев) → `eval/LATEST.md` | да |
| `pnpm results --group DEV --set dev` | выгрузка результатов в формате организаторов с проверкой | нет (берёт готовые оценки) |

Пакетная оценка набора из терминала: `pnpm batch --group <group_id>`.

## Сдача результатов (формат организаторов, Results JSON 1.0)

Файлы по приложению к гайду: `results/dev/results.json` (DEV, 65 диалогов) и `results/prod/results.json` (контроль, ровно 10).

```bash
# DEV: выгрузить уже готовые оценки
pnpm results --group DEV --set dev

# Контроль (1 час до стоп-кода): одной командой загрузить набор, оценить, выгрузить, проверить и отправить в Git
pnpm results --group <group_id_контроля> --set prod --run --push
```

Перед записью файл проверяется по правилам приложения: одна запись на диалог, без повторов ID, все 8 критериев
(`contact, discovery, identification, consultation, empathy, dialogue, closure, critical`) с допустимыми значениями,
`final_score` 0–100 с двумя знаками, `critical_flag` совпадает с `critical`, для prod — ровно 10 записей.
Неоценённый диалог выгружается со `status: "error"` и причиной, без подмены нулём.
Название команды — `CQA_TEAM_NAME` в `.env`. В интерфейсе: «Диалоги» → выбрать набор → кнопка **results.json**.
Если на контроле заменят критерий, укажите его код в редакторе чек-листа (поле «в выгрузке»).

## Что умеет

**Контур 1 · Оценка**
- **Редактор чек-листа** (вкладка «Чек-листы»). Можно добавлять, удалять и переставлять критерии и секции. У критерия настраиваются формулировка, вес, тип ответа (Да/Нет, шкала, флаг без баллов), доступность N/A и его условие. У шкалы задаются ступени. Есть поле уточнений для ИИ и общие правила. Каждое сохранение создаёт новую версию, старые оценки хранят снимок своей версии. Есть кнопки «Создать копию» и «Сбросить к исходному».
- **Загрузка диалогов**:
  - через API организаторов по `group_id` (запрос идёт с сервера, поэтому ошибки CORS нет);
  - из файла `.json` (ответ API, массив записей или одна запись);
  - вставкой текста в формате `[MM:SS] operator: текст`.
- **Оценка.** Можно оценить один диалог или пакет из очереди с прогрессом. Очередь сохраняется в `storage/jobs.json`: после перезапуска сервера оценка продолжается с места остановки, а прогресс виден и после перезагрузки страницы. Реплики бота и системные события передаются модели как контекст.
- **Результат.** По каждому критерию показываются:
  - ответ, баллы и вес после перераспределения;
  - объяснение;
  - реплики-доказательства (по клику — переход к сообщению);
  - для пропущенного действия или N/A — проверенный участок разговора;
  - причина N/A.

  Также показываются итог, результаты по секциям и отдельная отметка о грубой ошибке.

**Экран «Анализ разговора»** (по макету организаторов): дорожки «Клиент» и «Оператор» с волной из настоящей записи
(для чатов — хронология реплик), выделение фрагмента, плеер; «Расшифровка» с подсветкой текущей реплики;
«Оценка качества» — кольцо итога, критерии с ✓/✗ и баллами, «Почему снижена оценка», кнопки «Перейти к фрагменту»
и «Оспорить оценку».

**Аналитика** для руководителей: средний итог и медиана, выполнение по каждому критерию, распределение итогов,
средний итог по языкам, грубые ошибки, апелляции, диалоги, требующие внимания. Каждый график можно открыть таблицей.

**Контур 2 · Работа с результатом**
- **Карточка диалога.** Транскрипт и результат открыты рядом. Ссылка в обосновании прокручивает транскрипт к реплике и подсвечивает её. Ссылку вида `#/c/<id>?m=<N>` можно передать коллеге. У звонков есть встроенный плеер: кнопка ▶ у каждой реплики и переход по доказательству перематывают запись к этому месту. Есть выбор скорости и ссылка на плеер организаторов.
- **Апелляция.** Пользователь выбирает критерий, пишет комментарий и при желании предлагает свою оценку.
- **Рабочее место проверяющего** (вкладка «Апелляции»). Проверяющий видит спорную оценку, обоснование ИИ, комментарий и фрагмент диалога с репликами-доказательствами. Он подтверждает или меняет оценку и указывает причину, после чего итог пересчитывается. В карточке видны исходная оценка ИИ, решение и финальный результат.
- **Обучение на апелляциях.** Если проверяющий изменил оценку, его причину одной кнопкой можно добавить в «Уточнения для ИИ» критерия. Создаётся новая версия чек-листа, и следующие оценки её учитывают.
- **Экспорт** последних оценок в CSV или JSON.

**Живая оценка.** Критерии появляются по мере готовности: «Критерий 3 из 8 · 24 с». Можно остановить: модель прекращает работу, неполная оценка не сохраняется.

**Метрики разговора** — считаются кодом по времени реплик, без ИИ: время ответа оператора, долгие паузы и ожидание, предупреждения об ожидании, доля речи оператора, у звонков — перебивания. Паузы кликабельны.

**Точность ИИ в «Аналитике»** — совпадение с экспертной разметкой по критериям и языкам из последнего `pnpm eval`. Таблица «Модели: локальная и облачная» сравнивает все замеренные модели: совпадение, ошибку итога, время и стоимость одной оценки. Чтобы добавить облачную строку, задайте `ANTHROPIC_API_KEY` и `CQA_PROVIDER=anthropic`, затем запустите `pnpm eval --run --set dev`.

**Стоимость и время** каждой оценки видны в карточке: модель, секунды, токены, $ (у локальной модели — бесплатно).

## Как устроена оценка

```
транскрипт + чек-лист ──► промпт ──► LLM (структурированный JSON по схеме)
                                         │
                       валидация ◄───────┘  допустимые ответы, ступени шкалы, номера реплик
                           │
                 расчёт баллов кодом  ──► итог, секции, грубые ошибки
```

- **Промпт строится из текущей конфигурации чек-листа.** Новый или изменённый критерий применяется сразу, без правки кода. Во вкладке «Трассировка оценки» видны промпт и ответ модели. Это подтверждает, что система действительно анализирует новый диалог, а не воспроизводит заготовки.
- **Модель только выбирает ответ** по каждому критерию и указывает реплики. Арифметику делает детерминированный код (`server/scoring.js`), он покрыт тестами:
  - «Да» даёт полный вес, «Нет» — ноль;
  - шкала пересчитывается пропорционально весу (верхняя ступень даёт полный вес);
  - вес критериев с N/A пропорционально перераспределяется, чтобы максимум остался 100;
  - итог округляется до двух знаков;
  - если применимых критериев нет, итог не рассчитывается;
  - грубая ошибка отмечается отдельно.
- **Защита от ошибок модели.** Ответ вне допустимых значений приводится к ближайшей ступени, а запрещённый N/A заменяется на «Нет»; при этом показывается предупреждение. Несуществующие номера реплик отбрасываются.
- **Подсказки модели из транскрипта:** номер первого сообщения оператора и длинные паузы оператора после реплик клиента (для критерия об ожидании).
- **Факты проверяет код, а не модель.** Небольшая модель путает очевидное: цитирует «До свидания» и пишет, что прощания не было. Поэтому `server/rules.js`:
  - «Установление контакта» решает сам: приветствие на языке клиента и имя в первом сообщении оператора. Совпадение с эталоном 26 из 26;
  - для «Завершения» находит прощание и передаёт модели только вопрос «был ли итог»;

  Ответ правила помечен в карточке «проверено правилом».
- **Цитаты сверяются с расшифровкой.** Модель часто сдвигает номер реплики на 1–2 или копирует служебную приставку строки. Код находит цитату в тексте и исправляет ссылку. Цитата, которой нет в диалоге, — повод для проверки.
- **«Нужна проверка человеком».** Оценка попадает в очередь (фильтр в списке диалогов), если найдена грубая ошибка, модель противоречит себе в условии N/A, прогоны разошлись, есть снижение без реплики-основания или цитата не найдена. Проверяющий подтверждает оценку или оспаривает её.
- **Перепроверка спорных критериев** (опционально, `CQA_RECHECK=2`). Если у критерия есть повод для сомнения, модель отвечает ещё два раза с другим `seed`, и выбирается ответ большинства. В карточке видно «перепроверено» и все три ответа. По умолчанию выключена: на 26 диалогах она изменила 4 ответа из 14 перепроверенных, прироста точности не дала, а оценка шла на ~45% дольше (замер `eval/reports/2026-11-07T17-34-07.json`).
- **Голосование (опционально).** При `CQA_RUNS=3` выполняется несколько независимых прогонов, ответ выбирается большинством, для шкалы берётся медиана. В UI показывается согласие прогонов.

## Модель и стоимость

| Режим | Настройка | Примечание |
|---|---|---|
| Облако (по умолчанию) | `CQA_PROVIDER=anthropic`, `CQA_MODEL=claude-opus-5-5`, `CQA_EFFORT=high` | Claude Opus 5.5: $4 за 1M входных токенов, $20 за 1M выходных. Системный промпт кэшируется. |
| Локальная модель | `CQA_PROVIDER=ollama`, `CQA_MODEL=qwen2.5:7b-instruct`, `OLLAMA_NUM_CTX=12288`, `CQA_CONCURRENCY=1` | Через Ollama, бесплатно. На RTX 4050 (6 ГБ) — около 60–80 с на диалог. Точность ниже, особенно на KZ. |

**Примерная стоимость одной оценки** (1 вызов модели на диалог):
- входные токены: около 3–4 тыс. на чек-лист и правила (кэшируются) плюс 1–3 тыс. на транскрипт чата, до 6 тыс. на звонок;
- выходные токены: около 2–4 тыс., включая рассуждение.

Итого **≈ $0.05–0.10 за диалог** на Opus 5.5 при `effort=high` и примерно в N раз больше при `CQA_RUNS=N`. Точная стоимость каждой оценки считается по фактическим токенам и показывается в карточке и в прогрессе пакета. Для экономии можно задать `CQA_EFFORT=medium` или `CQA_MODEL=claude-sonnet-5-5`.

## Лендинг и деплой

- `public/index.html` — лендинг о проекте с живой статистикой из API (если API недоступен, блок статистики скрывается).
- `public/app.html` — само приложение.

**Демонстрация** — с ноутбука: `pnpm start`. Модель (Ollama) работает локально, поэтому сервер должен быть запущен на машине с моделью.

**Публичная ссылка на работающее приложение** — туннель Cloudflare (бесплатно, без регистрации):
```bash
cloudflared tunnel --url http://localhost:3000
```

**Лендинг на Vercel** (статическая страница; приложение и API остаются на ноутбуке):
```bash
pnpm dlx vercel deploy public --prod
```
Кнопка «Открыть приложение» ведёт на `app.html`. Чтобы она вела на туннель, откройте лендинг с параметром `?app=https://<адрес-туннеля>/app.html&api=https://<адрес-туннеля>` — тогда подтянется и живая статистика.

## Встраивание в Dynamics 365

Интерфейс — это один веб-компонент `<cqa-app>` (`public/cqa.js` + `public/cqa.css`) на чистом HTML, CSS и JS без сборки. Все стили ограничены селектором `cqa-app`, поэтому не конфликтуют со стилями страницы. Чтобы встроить:

1. Загрузите `cqa.js` и `cqa.css` как HTML web resources.
2. Разместите `<cqa-app api-base="https://<адрес сервиса>"></cqa-app>`.

Сервер разрешает CORS; ограничить разрешённый адрес можно через `CQA_CORS_ORIGIN`.

## Структура

```
server/index.js            HTTP-сервер и REST API (без фреймворков)
server/evaluator.js        промпт, вызов LLM, валидация, сверка цитат, поводы для проверки, голосование, очередь
server/rules.js            факты, которые проверяет код: представление оператора, прощание
server/metrics.js          метрики разговора по таймингам: ответ оператора, паузы, перебивания
server/scoring.js          расчёт баллов по правилам чек-листа
server/llm.js              провайдеры: Anthropic (Claude) и Ollama
server/dataset.js          API организаторов, импорт, нормализация, аудио
server/defaultChecklist.js исходный чек-лист из PDF
server/db.js               файловое JSON-хранилище (./storage)
public/                    интерфейс (веб-компонент)
scripts/batch.js           пакетная оценка из терминала
scripts/eval.js            замер точности на эталоне (eval/gold)
scripts/check.js           проверка готовности к демонстрации
test/                      тесты расчёта, API, правил и метрик
```

## Сценарий демонстрации (5 минут)

1. **Интерфейс и диалог.** Откройте список (набор DEV), затем любой чат или звонок.
2. **Оценка.** Нажмите «Переоценить» — критерии появляются по одному (около минуты на локальной модели). Покажите баллы, обоснования, пометку «проверено правилом» и переход по реплике-доказательству; у звонка — перемотку записи и метрики разговора. Покажите N/A с перераспределением весов и итог.
3. **Апелляция.** Фильтр «Нужна проверка» в списке показывает, где ИИ сомневается. Нажмите «Оспорить» у критерия и оставьте комментарий. Во вкладке «Апелляции» измените оценку с указанием причины, покажите новый итог и кнопку «Добавить в чек-лист».
4. **Изменение критерия.** Во вкладке «Чек-листы» измените или замените критерий, нажмите «Сохранить новую версию», затем «Применить к диалогам» и «Оценить все показанные».
